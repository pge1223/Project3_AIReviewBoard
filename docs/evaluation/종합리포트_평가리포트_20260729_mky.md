## 1. 평가 대상 시스템 · 모델

| 구성 | 내용 |
|---|---|
| 파이프라인 | 공고문 rubric 자동 추출 → 항목별 근거 검색(RAG) → AI 위원 독립 채점 → 결정론 점수 엔진 → 위원장 종합(백그라운드) |
| 오케스트레이션 | LangGraph (위원 병렬 노드 + 점수 노드 + 위원장 노드, 실패 노드 재시도) |
| 채점 위원 | 기획 전문가·개발 전문가 2인 (2026-07-28 전환, 항목별 주담당 1 + 보조 0~1 배정) |
| LLM | OpenAI gpt-4o-mini (위원·rubric 추출), temperature=0 |
| 검색 | KURE-v1 임베딩 + Chroma, 역할 기반 재랭킹 (용준 담당 레이어) |
| 점수 계산 | LLM이 아닌 Python 결정론 규칙 (Decimal, criterion_owner 가중합 + 결정론 상한) |

핵심 설계: **LLM은 "의견(제안 점수·지적·근거 인용)"만 내고, 최종 점수는 결정론 코드가 확정**한다.
같은 문서 → 같은 상한, 같은 위원 제안 → 같은 총점. 평가는 이 결정론 층이 실제로 신뢰성을
보장하는지, LLM 층의 분산·앵커링이 결과를 흔들지 않는지를 측정한다.

## 3. 지표 체계

### 3.1 강의 가이드(9장 RAG Triad·G-Eval)와 본 시스템 지표의 매핑

본 시스템의 출력은 단답형 QA가 아니라 **"회의록 + 항목별 채점"**이라 Ragas 표준 파이프라인을
문답 그대로 돌릴 수 없다. 그래서 RAG Triad의 각 축을 시스템 구조에 맞는 측정 가능한 자체
지표로 대응시키고, 검색 레이어는 표준 IR 지표로 측정한다.

| 가이드 지표 | 본 시스템 대응 지표 | 측정 방법 |
|---|---|---|
| Faithfulness (환각 제어) | **근거 기반성** — 위원 지적↔원문 문장 1:1 검증(issue_refs), 근거 게이트(근거 없으면 숫자 점수 차단), 인용문 원문 존재 검사 | 결정론 문자열 검증 + 게이트 통과율 (실험 4·8) |
| Context Precision/Recall | **검색 품질** — Recall@K, Precision@K, Hit Rate@K, MRR, nDCG@K | `ai/rag/evaluation` 오프라인 하네스(36케이스 평가셋, top_k=5) — RAG 레이어(용준) 실측: Recall@5 0.944 → **1.000**(타입 라우팅 적용 후), MRR@5 1.000, 검색 실패율 0, 평균 289ms (`reports/rag_eval_current_v6_36_*`, 2026-07-28, 검수 전 참고치) |
| Answer Relevance | **기준 충실성** — 위원이 rubric 밖 항목을 지어내지 않는가 | rubric 3중 차단(추출 검증·화이트리스트·배정 강제) 위반 0건 (실험 3) |
| G-Eval (LLM-as-Judge) | **위원 채점 자체가 rubric 기반 Judge** — 판정 밴드(엄정 채점 + 상향 변별)로 구간을 강제하고, 결정론 상한이 과대 점수를 차단 | 버전 시리즈 변별력 실측 (4장) |
| (가이드 9.5 개선 실험 기록) | **Before/After 실험 9건** — 프롬프트·게이트·상한 변경 전후 점수 변화 표 | 개선실험 문서 + 본 리포트 4장 |

### 3.2 자체 설계 지표 6축 (상세 정의는 설계 가이드 문서)

1. **재현성** — 동일 입력 반복 시 점수 편차 (파이프라인 결정론 + temperature 0)
2. **변별력** — 품질 단계별 버전 시리즈의 의도 순위를 점수가 재현하는가
3. **근거 기반성** — 지적·인용이 실제 원문에 존재하는가 (Faithfulness 대응)
4. **기준 충실성** — 공고문 rubric 밖 항목·배점을 지어내지 않는가
5. **주관성 배제** — 측정 불가 항목(가치 판단·가점)을 채점에서 제외하고 사유를 명시하는가
6. **표시 일관성** — 화면의 판정·점수가 저장 데이터와 결정론으로 일치하는가

## 4. 실측 결과

### 4.1 변별력 — 버전 시리즈 최종 곡선 (배포 서버 실측, 2026-07-29)

| 버전 | 총점(/85) | 의도 순위 | 결과 |
|---|---|---|---|
| v1.0 | **29.5** | 최하 | ✅ 최하 분리 (상한 지배) |
| v1.1 | 67 | 중하 | ✅ 중위 |
| v1.2 | 65 | 중상 | ⚠️ v1.1 대비 −2 (분산 범위 내, 4.3절) |
| v1.3 | **73** | 최고 | ✅ 최고 분리 (+8) |

**해석**: 설계상 격차가 큰 구간(부실 v1.0 ↔ 나머지, 완성 v1.3 ↔ 나머지)은 안정적으로
분리된다(각각 −35.5, +8). 격차가 작은 구간(v1.1 ↔ v1.2)은 LLM 제안 분산(±2점 수준)에
묻힌다 — 이 지표의 분해능 한계로 정직하게 기록한다(5장 한계).

### 4.2 재현성 — 부실 문서 총점의 결정론 재현

v1.0의 서버 총점 29.5는 **로컬에서 LLM 없이 정확히 재현**된다. 결정론 상한(캘리브레이션)이
4개 항목 전부에서 발동해 위원 제안과 무관하게 총점이 상한 합으로 고정되기 때문이다:

| 항목(배점) | 발동 신호 | 상한 |
|---|---|---|
| 목표 부합성 (15) | S6(분량 깊이) | 6.00 |
| 기술성·혁신성 (30) | S6 | 12.00 |
| 실현 가능성 (30) | S6+S2(정량 없음)+S4(실행 실체 없음)+MULTI(복합 결핍) | 7.50 |
| 확산성·효과성 (10) | S6+S2 | 4.00 |
| **합계** | | **29.50 = 서버 총점** |

반대로 v1.1~v1.3은 4개 항목 모두 상한 미발동 — 점수가 전적으로 위원 제안에서 나온다.
즉 "하한 신뢰성은 결정론이 보장하고, 상향 변별은 LLM 층이 담당"하는 역할 분리가 실측으로
확인된다. 파이프라인 자체 결정론은 stub 반복 실행 편차 0으로 별도 검증되어 있다
(`ai/meeting/tests/test_consistency.py`, `run_consistency_check` n=3).

### 4.3 개선 실험 9 — 65점 앵커링 수리 (Before/After, 2026-07-28~29)

가이드 9.5 "개선 실험 기록" 절차에 따른 최신 실험. 기존 실험 1~8은
[개선실험 문서](../prompts/Comprehensive_Report/종합리포트_개선실험_Before_After.md) 참고.

- **문제 실측**: 서로 다른 문서 4개(3.2k~10.7k자)가 전부 총점 **정확히 65**로 수렴.
  결정론 상한은 전부 미발동으로 확인 → 원인은 위원 프롬프트의 엄정 채점 지침이 하향
  규칙만 갖고 있어, LLM이 좋은 문서에도 strong(85~100%) 대신 adequate 구간의 라운드
  넘버(12/15 + 23/30 + 22/30 + 8/10 = 65)에 앉는 **앵커링**.
- **수리**: 하향 규칙과 대칭인 [상향 변별] 규칙 추가 — ①실명 출처 ②정량 실적
  ③완료형 실행+검증 ④차별성 비교 4요건 중 3개 이상이면 strong(85%+) 강제, 2개면
  adequate 상단(75~84%). 과대 점수는 결정론 상한이 별도로 방지하므로 안전.
- **결과**:

| | v1.0 | v1.1 | v1.2 | v1.3(완성본) |
|---|---|---|---|---|
| Before (하향 규칙만) | 29.5 | 65 | 65 | **65** (앵커) |
| After (+상향 변별) | 29.5 | 67 | 65 | **73** (+8 분리) |

- **해석**: 부실 문서 점수는 그대로(상한 안전망 작동 확인), 4요건을 채운 문서만
  위로 분리 — 변별력이 아래·위 양방향으로 열렸다.

## 5. 한계와 향후 계획

1. **미세 품질 차 분해능**: v1.1↔v1.2처럼 격차가 작은 구간은 LLM 제안 분산(±2점)에
   묻힌다. TST-002 반복 실측(동일 문서 서버 3회 재평가)에서 총점 편차 0~3점으로 허용범위
   (10점) 이내임을 확인했고(통합 리포트 1.4절), 항목별 제안 점수의 신뢰구간 표기가
   다음 단계다 (하네스: `ai/meeting/quality/consistency.py`, stub 기준선 편차 0).
2. **Ragas 표준 파이프라인 직접 적용**: 채점(회의록)이 아닌 **멘토 후속 질문·답변
   로그**는 문답 형태라 Ragas Faithfulness·Answer Relevance를 표준 그대로 적용
   가능 — 대화 로그 축적 후 골든셋 20~50문항으로 배치 측정 계획.
3. **검색 레이어 실측값 연동**: RAG 담당(용준)의 하네스 실측이 확보되어 3.1절에 병기함
   (Recall@5 0.944→1.000, 36케이스, 검수 전 참고치) — 사람 검수 완료 후 확정치로 갱신 예정.
4. **테스트셋 규모**: 현재 1개 과제 × 4버전. 도메인이 다른 과제 시리즈를 2~3세트
   추가해 변별력 결과의 일반성을 확인할 필요가 있다.
