## 담당 파트 (한 줄)

**LangGraph 회의 오케스트레이션 · Rubric 자동 추출 · 결정론 점수 엔진 · 종합 리포트(버전 추적)**
— "AI 위원의 의견과 코드의 확정을 분리해, 신뢰할 수 있는 채점을 만들었다"

## 사용 기술

LangGraph(LangChain 생태계 그래프 오케스트레이션), OpenAI gpt-4o-mini(temperature 0),
Python(Decimal 결정론 점수 엔진), FastAPI·MongoDB 연동, React(종합 리포트 화면),
pytest(회귀 테스트), matplotlib(평가 시각화)

⚠️ 표기 주의(팀 합의 A안): **LangChain 검색 체인·RAG는 용준님 산출물** — 경이 파트
슬라이드에 "LangChain 구현"으로 쓰지 말 것. 검색 수치를 인용할 땐 "RAG(용준) 실측" 표기.

## 슬라이드 구성 제안 (3블록 — 시간 없으면 ②만)

### ① 무엇을 만들었나 (그림: `최종발표_선별그림_20260729_X/1_아키텍처_fig12.png`)

- 공고문 → Rubric 자동 추출(3중 검증) → 위원 2인 병렬 채점 → **결정론 점수 엔진** → 종합 리포트 → 수정본 재제출 반복
- 핵심 설계: **"LLM은 의견, 코드가 확정"** — 최종 점수 = min(위원 제안, 문서 원문 결정론 상한)

### ② 결과 — 버전이 좋아지면 점수가 따라온다 (그림: `3_최종곡선_fig8.png`)

- 품질 단계별 4버전 골든셋 실측: **29.5 → 67 → 65 → 73** (부실 문서 최하 분리, 완성 문서 +8 분리)
- 멘트: "문서에 실명 출처·정량 실적·검증 결과를 채우면 점수가 올라가고, 비우면 코드가 막습니다."

### ③ 신뢰성 — 점수를 믿을 수 있는 이유 (그림: `5_결정론재현_fig9.png`, 보조: `4_앵커링실험_fig7.png`)

- 부실 문서 총점 **29.5 = 결정론 상한 합(6+12+7.5+4)** — LLM 없이 로컬에서 같은 값 재계산
- 동일 문서 반복 평가(TST-002) 편차 **0~3점** (허용 10 이내), 파이프라인 자체 편차 0
- 개선 실험 **9건** Before/After 기록 (65 앵커링 발견 → 상향 변별 규칙으로 수리)
