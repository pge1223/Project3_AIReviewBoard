## 0. 무엇을 평가하는가 — "종합 리포트"의 품질 정의

종합 리포트는 **공고문 배점표를 근거로 제출 문서를 채점하고, 버전(v1.0→v1.n)마다
해결/신규/잔존 지적을 추적하는 개인 맞춤형 피드백 루프**다(LangGraph 위원 회의 → 결정론
점수 엔진 → 버전 비교). 이 시스템의 품질은 5개 축으로 정의한다:

| 축 | 질문 | 왜 중요한가 |
|---|---|---|
| **재현성** | 같은 문서를 다시 채점하면 같은 점수가 나오는가? | 점수가 흔들리면 버전 추적(상승/하락)이 무의미해짐 |
| **변별력** | 좋은 문서와 나쁜 문서의 점수가 실제로 갈리는가? | 다 비슷한 점수면 피드백 루프가 성립 안 함 |
| **근거 기반성** | 채점·지적이 실제 문서 원문에 근거하는가? (환각 제어) | 지어낸 근거는 사용자를 속이는 것 — 서비스 신뢰의 핵심 |
| **기준 충실성** | 채점 기준(rubric)이 공고문 배점표 그대로인가? | 기준 자체가 지어낸 것이면 이후 전부 무효 |
| **표시 일관성** (07-27 추가) | 같은 저장 데이터가 언제 봐도 같은 판정·같은 해결/신규/잔존으로 표시되는가? | 접속·재분석 시점마다 표시가 달라지면 점수·버전 추적을 믿을 수 없음 |

## 1. 지표 정의·측정 방법·실측값

### 1.1 재현성 (Score Reproducibility)

| 항목 | 내용 |
|---|---|
| 정의 | 동일 문서·동일 rubric 재채점 시 총점 편차 |
| 측정 방법 | 같은 프로젝트에서 같은 문서를 3회 재분석해 총점 비교 |
| 장치 | 채점·추출 LLM `temperature=0` + `seed` 고정, 최종 점수는 Python 결정론 계산 |
| **실측** | 개선 전 **31.5 ↔ 64 (편차 ±32.5)** → 개선 후 **54.5 / 56 / 55.5 (편차 ±1.5)** |

### 1.2 변별력 (Discriminative Power)

| 항목 | 내용 |
|---|---|
| 정의 | 품질이 다른 문서 간 총점 격차 |
| 측정 방법 | 같은 공고문·rubric으로 저품질/우수 문서 쌍을 채점해 격차 확인 (엄격화가 우수 문서를 깎지 않는지 역검증 포함) |
| 장치 | 판정 밴드 캘리브레이션(critical_risk 0~40% … strong 85~100%) + [엄정 채점] 2단계 강제 + 근거 신호 기반 결정론적 점수 상한(calibration) |
| **실측** | 근거 없는 문서 **21.5점** vs 잘 쓴 문서 **77점** (1차) / **55.5점** vs **81점** (2차, 데이터 항목 55% vs 90%) — 우수 문서는 깎이지 않음 |

### 1.3 근거 기반성 (Groundedness — Faithfulness 대응)

| 항목 | 내용 |
|---|---|
| 정의 | 지적·인용이 실제 색인 문서 원문에 존재하는 비율 |
| 측정 방법 | ① 지적 속 인용 `(p.N) '문장'`을 결정론 파싱 후 **제출 문서 원문 존재 검증**(`issue_refs.verified`) — 원문에 없으면 화면 표시 차단 ② 화면의 모든 인용은 RAG evidence(색인된 원문 청크)에서만 렌더 — 프론트가 문장을 생성하지 않음 ③ evidence의 quote(위원 LLM 자기보고)도 **색인된 청크 원문에 실제 존재할 때만** 표시, 아니면 청크 원문으로 대체·청크 미상 제외(07-26 추가 — 붙임2 p.9에 없는 문장이 실제 파일명·페이지로 표시되던 사고 실측 차단) |
| 장치 | reviewer 프롬프트 [지적 작성 규칙 — 문장 단위 인용] + transform 단계 원문 검증 + UI는 verified=true만 표시 |
| **실측(단위 검증)** | 원문에 있는 인용 → `verified=true` / 지어낸 인용 → `verified=false`(표시 안 됨) / 인용 없는 지적 → ref 없음(폴백) — 3케이스 모두 자동 판별 확인 |

### 1.4 기준 충실성 (Rubric Fidelity)

| 항목 | 내용 |
|---|---|
| 정의 | 채점 rubric의 항목·배점이 공고문 원문과 일치하는 정도 |
| 측정 방법 | 결정론 검증 3중: 항목명이 공고문 원문에 실제 등장하는지 / 배점 숫자가 원문에서 확인되는지(첫 부문 열로 강제 정렬) / 실패 시 지어내지 않고 폴백 + UI에 "공고문 기준 아님" 정직 라벨 |
| **실측(사고 → 차단)** | ① 잘못된 URL 스크랩(43자) → LLM이 기본 4범주 지어냄 → **사전 가드가 호출 차단** ② 신청서식 제목 4개×25점 균등 배분 지어냄 → **배점 원문 확인에서 거부** ③ 부문 열 혼용(확산성 25←우수사례 열) → **원문 첫 열 값으로 강제 보정(25→10)** — NIA 실증·PoC 기준 **만점 85점**(15+30+30+10, 안전성·윤리성 10 제외) 정확 재현 |

### 1.5 주관성 배제 (Measurability Scoping)

| 항목 | 내용 |
|---|---|
| 정의 | 정성 판단이 필요한 항목을 자동 채점에서 제외하고 그 사유를 공개 |
| 장치 | measurable 분류(주관 항목 `excluded_criteria`로 분리·사유 표기), 가점 요소 별도 분리, 만점=측정 가능 항목 배점 합, 상단 "총점은 참고용" 고지 |
| **실측** | 안전성·윤리성(10점) 제외 + 사유 문구 자동 생성·표시, 점수 체계표에 채점/제외 구분 렌더 확인 |

### 1.6 표시 일관성 (Display Determinism) — 2026-07-27 추가

| 항목 | 내용 |
|---|---|
| 정의 | 같은 저장 데이터가 접속·재분석 시점과 무관하게 같은 판정·같은 해결/신규/잔존으로 표시되는 정도 |
| 측정 방법 | 실측 모순 사례 재현 — ① 판정 라벨 vs 최종 점수 비율 대조 ② v1.0→v1.1 해결됨/신규 목록의 중복·모순 대조 |
| 장치 | 판정 = 최종(보정 후) 점수 비율의 결정론 밴드(85/65/40% — reviewer_prompt와 동일 경계) · 해결됨 = 직전 지적 매칭 검증(2-gram Dice ≥0.66/포함, 1건당 1건) · 잔존 = 핵심 주제 토큰 매칭(절반 이상 겹침) — 전부 표시 계층이라 저장 데이터 불변·기존 회의 소급 적용 |
| **실측** | 「적정」인데 6/15점(40%) 모순 → 항상 「보완 필요」 고정 / 해결됨 표시 **6→2건**(v1.0→v1.1) / "해결됨 + 같은 지적 신규" 동시 노출 제거 — 오합병 검증: "확산 계획"↔"성과 지표(KPI)" 주제 겹침 0으로 구분 유지 |

## 2. 가이드북 9장(평가 지표) 지표와의 매핑

| 가이드북 지표 | 종합 리포트에서의 대응 | 상태 |
|---|---|---|
| **Faithfulness** (답변이 근거 문서에 기반) | 1.3 근거 기반성 — issue_refs 원문 검증 + evidence-only 렌더 + rubric 원문 검증(1.4) | **자체 장치로 상시 강제** (Ragas 배치 측정은 RAG 공동 영역) |
| **Answer Relevance** | 지적·제안이 rubric criterion(공고문 세부 기준)에 귀속되어 생성됨 — 항목 밖 의견은 evidence 게이트에서 차단 | 구조적으로 보장 |
| **Context Precision/Recall** | 위원별 role-aware 검색 + 근거충족도 게이팅(RAG-003/004/005) | **용준(RAG) 담당 영역** — 종합 리포트는 그 출력을 소비 |
| **G-Eval (LLM-as-Judge)** | 위원 채점 자체가 "rubric을 준 LLM Judge" 구조 — 단, 판정 밴드·결정론 상한·seed로 Judge의 주관·편차를 통제 | 자체 구현 (통제 장치 포함) |
| 시스템 지표(TTFB·비용) | 회의 1회당 LLM 호출 상한(`_MAX_LLM_CALLS_PER_MEETING`)·호출 로그 | 백엔드 로그 기반(윤한 영역과 공동) |

## 3. 평가 실행 방법 (가이드북 9.5 절차 대응)

1. **테스트셋**: 품질 단계가 다른 문서 세트(근거 없는 저품질 / 중간 / 우수)를 같은 공고문으로 채점 — 본 레포에서 사용한 실측 세트와 재현 스크립트 경로는 devlog(2026-07-23~26)에 기록.
2. **자동 검증**: `ai/meeting/tests/` **366개 테스트** (rubric 검증·보정·비교·calibration 포함) — 전부 통과 상태 유지.
3. **개선 실험 기록**: Before/After 문서 참조 → `종합리포트_개선실험_Before_After.md`.
4. **시각화**: `종합리포트_설계검증_시각화.ipynb` — 발표 PPT 삽입용 PNG는 `2026_07_25_시각화자료/`(fig1~4: 재현성·변별력·기준 충실성·근거 기반성) + `2026_07_27_시각화자료/`(fig5~6: 판정 표시 일관성·버전 추적 정확성).

## 4. 한 줄 요약 (발표용 핵심 메시지)

> "종합 리포트는 **공고문 원문만이 기준**이 되도록 3중 결정론 검증으로 지어내기를 차단하고,
> **seed 고정 + 결정론 점수 엔진**으로 같은 문서엔 같은 점수를, **캘리브레이션**으로 품질 차이엔
> 점수 차이를 보장한다. 모든 지적은 **제출 문서의 실제 문장(p.N)** 을 근거로 제시되며,
> 검증에 실패한 근거는 화면에 나오지 않는다."
