## 1. 담당 범위와 목표

사용자가 기획서를 업로드하면 공고문 기준으로 AI 위원이 채점하고, 수정본을 다시 내면
버전별 점수 곡선으로 개선을 추적하는 **종합 리포트** 기능의 백엔드 파이프라인 전체를
담당했다. 목표는 "점수를 보여주는 것"이 아니라 **"신뢰할 수 있는 점수"** — 같은 문서에
같은 점수가 나오고(재현성), 좋은 문서와 나쁜 문서가 점수로 구분되며(변별력), 모든
점수에 근거가 연결되는(근거 기반성) 상태를 실측으로 증명하는 것이다.

## 2. 아키텍처

> 그림: [fig12_architecture.png](2026_07_29_시각화자료/fig12_architecture.png)

```
공고문 업로드
  → Rubric 자동 추출 (LLM + 3중 검증, 프로젝트별 캐시 v9)
  → 항목별 근거 검색 (RAG — KURE·Chroma, 역할 기반 재랭킹)
  → AI 위원 2인 독립 채점 (기획·개발 전문가, 항목별 주담당 1 + 보조 0~1)
  → 결정론 점수 엔진 (Decimal 가중합 + 결정론 상한 + 근거 게이트)
  → 종합 리포트 (점수 체계표 · 판정 · 버전 곡선) → 수정본 재제출 반복
```

- **오케스트레이션**: LangGraph — 위원 병렬 노드, 점수 노드, 위원장 종합(백그라운드),
  실패 노드 재시도(체크포인트 재개), 진행률 통지.
  - 가이드가 권장한 LangChain 오케스트레이션과의 관계: LangGraph는 LangChain 팀이 만든
    그래프 기반 오케스트레이션 확장(langchain-core 위에서 동작)으로, 본 파트는 이것으로
    회의·채점 **흐름의 완성도**를 담당한다. 검색·생성 체인(LangChain Retrieval Chain)은
    RAG 담당(용준)의 산출물이며 본 문서에서는 실측값을 출처와 함께 인용만 한다.
- **위원 구성**: 아이디어 회의와 동일한 기획·개발 전문가 2인으로 통일(2026-07-28 전환).
  화면에 보이는 인물과 실제 채점 주체가 일치하고, 항목별로 배정된 위원의 점수만 집계된다.

## 3. 핵심 설계 결정 3가지

### 3.1 "LLM은 의견, 코드가 확정" — 결정론 상한

> 그림: [fig13_score_confirmation.png](2026_07_29_시각화자료/fig13_score_confirmation.png)

LLM 위원은 근거가 빈약한 문서에도 무난한 점수를 주는 관대화 경향이 있다(실측: 출처·수치
전무 문서에 ~82점). 그래서 채점과 별도로 문서 원문을 결정론 규칙(출처 실명 여부, 정량
표현, 미래형 비율, 실행 실체, 분량 깊이, 필수 요소)으로 검사해 항목별 **점수 상한**을
계산하고, 최종 점수 = min(위원 제안, 상한)으로 확정한다. 상한은 절대 점수를 올리지
않으며, 같은 문서면 언제나 같은 값이다.

### 3.2 Rubric 자동 추출 + 측정성 스코핑

공고문 배점표를 LLM으로 추출하되 **3중 검증**으로 기준 지어내기를 차단한다 — ① 배점
합계는 LLM 출력을 신뢰하지 않고 서버가 재계산 ② 위원 관점(perspective)은 페르소나
카드의 화이트리스트만 허용 ③ 항목별 배정 위원(주담당 1+보조 0~1) 밖의 채점은 집계에서
제외. 심사위원의 가치 판단이 필요한 항목(안전성·윤리성)과 증빙이 필요한 가점은 **점수에서
제외하되 사유를 점수 체계표에 명시**한다 — 이번 공고문 기준 100점 중 채점 85 / 제외 15.

### 3.3 근거 기반성 — 모든 판단에 원문 연결

위원 지적은 문제 문장을 원문에서 그대로 인용하고(1:1 검증, 지어낸 인용 차단), 항목별
근거가 부족하면 숫자 점수 자체를 차단하는 근거 게이트를 통과해야 한다. 버전 추적의
"해결됨" 표시도 새 버전 원문에서 근거를 재검증한다.

## 4. 평가 방법

> 그림: [fig14_experiment_coverage.png](2026_07_29_시각화자료/fig14_experiment_coverage.png) — 6축 × 실험 1~9 커버리지

- **지표 6축**: 재현성 · 변별력 · 근거 기반성 · 기준 충실성 · 주관성 배제 · 표시 일관성.
  가이드북 9장(RAG Triad·G-Eval)과의 매핑은 평가 리포트
  (`docs/evaluation/종합리포트_평가리포트_20260729_mky.md`) 3.1절.
- **골든셋**: 같은 과제의 수행보고서를 품질 단계별로 조작한 4개 버전(v1.0 부실 →
  v1.3 완성). 의도한 품질 순위가 정답 라벨이며, 조작이 실제로 단계적임은 채점 엔진과
  동일한 결정론 함수로 실측했다(글자수 1,202→10,688 · 실명 기관 0→5 · 정량 표현 5→164,
  `scripts/eval_report_signals_mky.py`).
- **절차**: 가이드북 9.5 — 골든셋 반복 실측 + 개선 실험 Before/After 기록(총 9건) +
  E2E QA 체크리스트(브라우저 시나리오).

## 5. 실측 결과

### 5.1 변별력 — 최종 버전 곡선 (배포 서버, 2026-07-28~29)

| | v1.0 | v1.1 | v1.2 | v1.3 |
|---|---|---|---|---|
| 총점(/85) | **29.5** | 67 | 65 | **73** |

품질 격차가 큰 구간은 안정적으로 분리된다(부실 −35.5, 완성 +8). 격차가 작은
v1.1↔v1.2의 −2는 LLM 제안 분산 범위로, 지표의 분해능 한계로 정직하게 기록한다.

### 5.2 재현성 — 부실 문서 점수의 결정론 재현

v1.0의 서버 총점 29.5는 결정론 상한 합(목표 6.0 + 기술 12.0 + 실현 7.5 + 확산 4.0)과
**정확히 일치**하며, LLM 호출 없이 로컬에서 재현된다. 파이프라인 자체의 결정론은 동일
LLM 출력(stub) 반복 실행 편차 0으로 별도 검증했다(`test_consistency.py`).

### 5.3 개선 실험 9 — 65점 앵커링 수리 (2026-07-28)

서로 다른 문서 4개가 전부 총점 정확히 65로 수렴하는 앵커링을 실측 — 상한은 전부
미발동이었으므로 원인은 위원 프롬프트가 하향 규칙(근거 빈약 시 상한 강제)만 갖고 있어
LLM이 좋은 문서에도 adequate 중간값(12/15+23/30+22/30+8/10=65)에 앉는 것이었다.
하향 규칙과 대칭인 **[상향 변별]** 규칙(실명 출처·정량 실적·완료형 실행+검증·차별성
비교 중 3요건 이상 → strong 85%+ 강제)을 추가한 결과, 부실 문서 하한은 유지된 채
완성 문서만 +8 분리됐다. 실험 1~8(재현성·상한·rubric 차단·인용 검증·주관성 배제·판정
일관성·버전 추적·근거 게이트)은 개선실험 문서 참고.

## 6. 트러블슈팅 요약 (전체 기록은 트러블슈팅 문서)

| 증상 (실측) | 원인 | 해결 |
|---|---|---|
| 재분석마다 rubric LLM 재추출 ~9초 | 캐시 저장 버전(3) < 판정 버전(7) 불일치 → 영구 미스 | 버전 상수 단일화 |
| 최고 문서만 점수 급락 | 본문 0자 섹션이 상한 검사에 매칭 → 결핍 신호 오발동 | 빈 섹션 매칭 제외 |
| 수정본 3번째 제출 시 버전 덮어쓰기 | 버전 누적 키 충돌 | 버전 누적 로직 수리(#150) |
| 서로 다른 문서 4개가 전부 65점 | 채점 프롬프트 하향 규칙만 존재(앵커링) | 상향 변별 규칙 추가 |
| 긴 수정본 제출 시 색인 에러 노출 | 색인 폴링 60초 후 무단 분석 진입 | 폴링 4분 + 명확한 에러 |
| 재테스트에서 점수 궤적 뒤집힘 | criterion_id의 LLM 드리프트가 상한 판별에 개입 | 원문 검증된 항목명 우선 판별 |

## 7. 한계와 향후 계획

1. **분해능**: 미세 품질 차는 LLM 분산(±2점)에 묻힘 → TST-002(위원 일관성)를 실제
   LLM 반복 실행으로 편차 분포 실측(하네스 준비 완료).
2. **표준 Ragas**: 문답 형태인 멘토 후속 대화 로그에 Faithfulness·Answer Relevance를
   표준 파이프라인으로 적용 계획.
3. **검색 레이어**: Recall@K·MRR·nDCG(`ai/rag/evaluation` 하네스, RAG 담당)와 병기 시
   레이어별 전체 그림 완성.
4. **일반성**: 타 도메인 과제 시리즈 2~3세트로 골든셋 확장.
