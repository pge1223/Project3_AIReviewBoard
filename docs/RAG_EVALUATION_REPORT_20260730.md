# AI Review Board RAG 성능 평가 리포트

- 작성일: 2026년 7월 30일
- 평가 대상: AI 아이디어 회의의 기획위원·개발위원 RAG 파이프라인
- 평가 범위: 문서 검색 품질, 답변 근거성, 답변 관련성, 검색 문맥 품질
- 평가 방식: 검색 평가 + RAGAS 기반 생성 평가

## 1. 평가 요약

AI Review Board의 RAG는 사용자가 등록한 공모전 URL·첨부 문서와 공식 외부 자료를
검색하여 기획위원과 개발위원의 발언 근거로 제공한다.

평가 결과, 정답 문서를 찾는 **검색 성능은 높은 수준**이었지만 검색 근거를 실제 발언에
충실하게 반영하는 **생성 품질은 개선이 필요한 상태**로 확인됐다.

| 영역 | 핵심 결과 | 판정 |
|---|---:|---|
| Recall@5 | 1.0000 | 양호 |
| Hit@5 | 1.0000 | 양호 |
| MRR@5 | 1.0000 | 양호 |
| 평균 검색 시간 | 288.6ms | 양호 |
| RAGAS Context Precision | 0.8086 | 양호 |
| RAGAS Context Recall | 0.8952 | 양호 |
| RAGAS Faithfulness | 0.2905 | 개선 필요 |
| RAGAS Answer Relevancy | 0.0716 | 개선 필요 |

> 검색 지표는 AI가 작성하고 아직 사람이 최종 검수하지 않은 36건의 평가셋에서 측정한
> 참고값이다. RAGAS 결과는 6개 케이스에서 생성된 35개 위원 발언을 대상으로 측정했다.

## 2. 평가 대상 파이프라인

```text
공고 URL·첨부파일·외부 공식 자료
→ 문서 파싱 및 페이지 경계 청킹
→ KURE-v1 임베딩
→ Chroma 벡터 저장
→ project_id·문서 역할 기반 검색
→ 기획위원·개발위원별 근거 선택
→ LLM 발언 생성
→ claim과 evidence 연결 및 grounding
→ UI의 근거 보기 영역에 인용 자료 표시
```

평가는 다음 두 구간을 분리하여 진행했다.

1. 검색 평가: 정답 문서 또는 청크가 상위 5개 결과에 포함되는지 측정
2. 생성 평가: 검색 문맥을 바탕으로 생성된 위원 발언이 근거에 충실하고 질문에 적절한지 측정

## 3. 평가 환경과 모델

| 구분 | 설정 |
|---|---|
| 애플리케이션 임베딩 모델 | `nlpai-lab/KURE-v1` |
| 벡터 데이터베이스 | Chroma |
| 평가 당시 컬렉션 | `project_documents_kure_v6` |
| 현재 애플리케이션 컬렉션 | `project_documents_kure_v7` |
| 검색 개수 | `top_k=5` |
| 위원 발언 생성 모델 | `gpt-4o-mini` |
| RAGAS 평가 모델 | `gpt-4o-mini`, temperature `0.0` |
| RAGAS 평가용 임베딩 | `text-embedding-3-small` |
| RAGAS 버전 | `0.2.15` |
| 실행 환경 | Python 3.11, RAGAS 전용 분리 환경 |

KURE-v1은 한국어 검색 문장을 벡터로 변환하는 애플리케이션 임베딩 모델이다.
`text-embedding-3-small`은 RAGAS가 Answer Relevancy 등을 계산할 때 사용한 평가용
임베딩이며, 실제 서비스 검색 모델을 대체하지 않는다.

현재 서비스는 손상된 v6 Chroma 인덱스를 보존하고 `project_documents_kure_v7`으로
전환한 상태다. 따라서 본 리포트의 검색 점수는 **v6 평가 스냅샷의 결과**이며, v7의 정식
점수로 간주하지 않는다.

## 7. 결과 해석

### 7.1 강점

- 정답 문서 검색 성능이 내부 평가셋에서 Recall@5·Hit@5 1.0을 기록했다.
- Context Precision 0.8086, Context Recall 0.8952로 필요한 문맥을 찾고 불필요한 문맥을
  줄이는 검색 단계는 비교적 안정적이었다.
- 기획위원과 개발위원을 분리하여 역할별 검색 결과와 발언을 평가할 수 있다.
- 평가 실행 중 RAGAS 지표 계산 오류나 누락이 발생하지 않았다.

### 7.2 개선이 필요한 부분

- 검색된 근거가 있어도 LLM 발언이 일반적인 전문가 제안으로 확장되면서 Faithfulness가
  낮아졌다.
- 회의의 개별 발언을 원래 평가 질문 하나와 비교하여 Answer Relevancy를 측정했기 때문에,
  진행 문장이나 보완 제안처럼 직접 답변이 아닌 발언이 낮은 점수를 받았다.
- 낮은 Answer Relevancy는 실제 발언의 장황함을 보여주는 동시에, 다중 턴 회의를 단일
  질의응답 방식으로 평가한 데이터 구성의 한계도 포함한다.
- 평가셋과 기준 답변이 아직 사람의 최종 검수를 받지 않았다.
- RAGAS 측정 이후 근거 우선 생성과 발언 축약 정책이 적용됐으므로 개선 결과를 다시
  측정해야 한다.

## 8. 평가 이후 적용한 개선 사항

2026년 7월 30일 기준으로 다음을 적용했다.

- 동일 `project_id`의 공고문·평가 기준 문서를 외부 자료보다 먼저 검색
- 기획위원과 개발위원의 검색 쿼리와 결과를 분리
- criteria → external → target 역할을 구분하고 target을 사실 근거로 과대 사용하지 않도록 제한
- 검색 근거가 있는데 인용하지 않은 경우 검색·생성 보정을 최대 1회 수행
- `claims[].evidence_refs`와 grounding을 통과한 근거만 UI에 연결
- RAG 원문을 말풍선에 복사하지 않고 evidence 영역에만 표시
- 기획·개발위원 검증 발언을 짧게 제한하고 반복 버블 제거
- 근거가 없는 제안은 문서 사실이 아니라 전문가 판단으로 구분

위 개선은 RAGAS 회귀 평가 이후 반영됐으므로 현재 리포트의 낮은 생성 점수에 아직
반영되지 않았다.

- 검색 평가 36건은 자동 일관성 검수를 통과했으며, RAGAS 6개 케이스는 소규모 회귀 평가셋이다.
- 평가 당시 컬렉션은 v6이며 현재 서비스 컬렉션은 v7이다.
- 6개 케이스는 회귀 확인용 소규모 표본이므로 전체 주제에 일반화하기 어렵다.
- 공모전 내부 문서 중심이며 최신 뉴스·정책·외부 공식 자료 케이스가 부족하다.
- 다중 턴 회의 발언을 단일 질문 기준으로 평가해 Answer Relevancy가 과도하게 낮아질 수 있다.

## 10. 재현 방법

### 10.1 검색 평가

백엔드와 평가 프로그램이 같은 Chroma 디렉터리를 동시에 열지 않도록 백엔드를 종료하거나
평가 전용 복사본을 사용한다.

```powershell
conda activate review-board
python -m ai.rag.evaluation.rag_quality.cli `
  --dataset reports/rag_eval_current_v6_36.jsonl `
  --mode retrieval `
  --top-k 5 `
  --output reports/rag_eval_v7_recheck
```

### 10.2 RAGAS 평가 데이터 생성

```powershell
conda activate review-board
python -m ai.rag.evaluation.rag_quality.export_ragas_dataset `
  --dataset ai/rag/evaluation/rag_quality/datasets/rag_eval_v6_regression_subset.jsonl `
  --top-k 5 `
  --output reports/ragas_export/dataset_v7_recheck.jsonl
```

### 10.3 RAGAS 실행

```powershell
conda activate ragas-eval
python ai/rag/evaluation/ragas_standalone/run_ragas_eval.py `
  --input reports/ragas_export/dataset_v7_recheck.jsonl `
  --output-dir reports/ragas_eval/v7_recheck `
  --model gpt-4o-mini `
  --embedding-model text-embedding-3-small
```

## 11. 결론

현재 RAG는 필요한 문서를 찾는 검색 단계에서는 높은 참고 성능을 보였다. 반면 검색한
근거를 위원 발언의 사실 주장과 정확하게 연결하는 생성 단계는 개선이 필요하다.

따라서 본 시스템의 현재 상태는 **“검색 기반은 안정화됐지만, 근거 중심 발언 생성은
고도화 중”**으로 평가한다. 이후 적용된 근거 우선 생성 정책을 동일 데이터셋으로
재측정하고 독립 표본 검토를 추가해야 최종 성능을 확정할 수 있다.
