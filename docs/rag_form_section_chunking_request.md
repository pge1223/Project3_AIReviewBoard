## 현상 (실측 — NIA 「2026 공공기관 AI 혁신 챌린지」 실증·PoC 프로젝트)

`붙임2_참가_신청_서식_실증PoC.pdf` 같은 **신청 서식류 문서**에서, 번호 달린 섹션 소제목과
바로 밑의 `<작성 요령>` 불릿이 **서로 다른 청크로 잘립니다**. 그 결과 위원이 인용한 청크가:

1. **제목만 있는 청크** — p.6 「3. 시스템 아키텍처 및 인프라 구성 적정성」: 인용 청크 text에
   제목 줄만 있고, 작성 요령 불릿 2줄("시스템 전체 아키텍처를 도식화하여…", "하드웨어·
   소프트웨어·네트워크 등 인프라 구성…")은 이웃 청크에 있음 → 리포트 보조 자료에
   "소제목만 있는 빈 블록"이 표시됨.
2. **같은 섹션의 중복 인용** — p.8 「2. AI 모델·알고리즘 설계 적정성」: "제목+불릿" 청크와
   "불릿만" 청크가 따로 존재해 같은 섹션이 두 번 표시됨.

## 왜 중요한가

서식의 섹션 소제목(「1. 성과 지표(KPI) 방안」, 「5. 목표 달성도 및 성과」 등)은 **제출 문서와
평가 항목을 잇는 다리**라서(경이·사용자 테스트 확인), 종합 리포트가 지적별 근거를 "파일명·
페이지 + 섹션 제목 + ㅇ 작성 요령 불릿" 형태로 보여줄 때 청크 하나에 제목과 본문이 같이
있어야 온전한 근거가 됩니다. 지금은 제목 따로/본문 따로라 근거가 반쪽으로 나옵니다.

## 요청

서식류(붙임 신청서 등) 문서 청킹 시 **"숫자. 제목" 패턴의 소제목 줄이 단독 청크가 되지 않고,
직후 본문(작성 요령 박스 포함)과 같은 청크에 묶이도록** 조정 부탁드립니다. 예:

- 소제목 줄을 청크 경계로 쓰되, 제목을 **다음 청크의 머리에 붙이는** 방식, 또는
- 청크 최소 길이를 보장해 제목 줄 단독 청크를 방지하는 방식

청크 메타의 `section`(섹션 제목)은 지금도 잘 들어오고 있어서, **제목-본문 분리만 해결되면**
됩니다. 스키마 변경은 필요 없습니다.

## 프론트 임시 방어 (이미 적용 — 청킹 개선 후에도 무해)

- 소제목만 있고 내용이 없는 보조 자료 블록은 숨김
- 같은 파일·페이지에서 한 블록이 다른 블록에 통째로 포함되면 더 완전한 쪽만 표시(중복 통합)

청킹이 개선되면 별도 프론트 수정 없이 완전한 블록(제목+불릿)이 그대로 표시됩니다.

## 재현 방법

1. NIA 실증·PoC 프로젝트(공고 자료: 붙임1 공고문 + 붙임2 신청 서식)에서 문서 분석 실행
2. 종합 리포트 → 위원 탭 → 지적 펼침 → Why? → STEP 2 "보조 자료" 펼침
3. 붙임2 p.6 인용 블록에서 「시스템 아키텍처 및 인프라 구성 적정성」 제목만 있는 청크 확인
   (Mongo `meetings.evidence[]`의 해당 chunk `text` 필드에서도 동일 확인 가능)

  `section` 메타가 없어 보조 자료에서 어느 소제목의 작성 요령인지 연결이 안 됩니다.

**추가 요청**: 소제목이 페이지 마지막 블록이고 직후 본문(작성 요령)이 다음 페이지에서

직전 페이지 제목을 이어주)도록 검토 부탁드립니다.
